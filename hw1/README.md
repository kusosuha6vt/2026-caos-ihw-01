# Картинная галерея — ИДЗ 1, вариант 16

Нестеров Дан Александрович · БПИ253 · C17 · libc/POSIX.

Последовательная имитация рабочего дня галереи: **один процесс, один поток**.

[Отчёт PDF](output/pdf/report.pdf) · [API HTML](docs/generated/html/index.html) ·
[Устройство модели](docs/design.md) · [Проверки](docs/verification.md)

## Быстрый запуск

Нужны CMake ≥ 3.20, C-компилятор и среда POSIX.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
./build/gallery --config configs/demo.env
```

| Сценарий | Команда |
|---|---|
| Короткая наглядная демонстрация | `./build/gallery --visitors 5 --capacity 2 --paintings 3 --delay-ms 50` |
| Интерактивный ввод | `./build/gallery --interactive` |
| Только итог | `./build/gallery --quiet` |
| Циклический обход с заданным seed | `./build/gallery --strategy cyclic --seed 7` |
| Работа до Ctrl+C | `./build/gallery --unlimited --delay-ms 5` |
| Пустой день | `./build/gallery --visitors 0` |
| Полная справка | `./build/gallery --help` |

## Возможности модели

- Самостоятельные записи посетителей, картин и функция допуска вахтёра.
- Ограничения вместимости галереи и числа зрителей у каждой картины.
- FIFO у входа и у каждой картины.
- Ожидание выбранной картины до освобождения места.
- Четыре стратегии выбора.
- Логические часы: переход сразу к ближайшему событию.
- Окончание просмотра раньше прибытия при равном времени.
- Порядок одновременных окончаний по ID посетителя.
- Место у картины зарезервировано до окончания просмотра.
- Воспроизводимость по seed; одинаковая входная нагрузка для всех стратегий.
- Настраиваемая задержка отображения без изменения результата модели.
- Переиспользование записей посетителей и лимит активных записей.
- Проверка инвариантов после событий.

| Стратегия | Выбор следующей неосмотренной картины |
|---|---|
| `ordered` | Минимальный номер |
| `random` | Равномерный случайный выбор |
| `least-crowded` | Минимум зрителей + ожидающих; при равенстве меньший номер |
| `cyclic` | `(start + k × step) mod M`, где `gcd(step, M) = 1` |

Для `cyclic` начало и шаг зависят от seed и ID. При одной картине шаг равен 0.

Пять проверяемых инвариантов:

1. Вместимость галереи не превышается.
2. Лимит зрителей у картины не превышается.
3. Посетитель смотрит не более одной картины одновременно.
4. Каждая картина засчитывается не более одного раза.
5. Выход освобождает место в галерее.

## Параметры и ввод

Приоритет: **defaults → файл → среда → CLI → интерактивный ввод**.

| Параметр CLI | Ключ файла / среды | По умолчанию | Допустимые значения |
|---|---|---|---|
| `--capacity` | `GALLERY_CAPACITY` | 20 | 1..10000 |
| `--paintings` | `GALLERY_PAINTINGS` | 7 | 1..256 |
| `--painting-capacity` | `GALLERY_PAINTING_CAPACITY` | 3 | 1..10000 |
| `--visitors` | `GALLERY_VISITORS` | 200 | 0..100000 |
| `--arrival-min`, `--arrival-max` | `GALLERY_ARRIVAL_MIN`, `GALLERY_ARRIVAL_MAX` | 1, 5 мс | 0..1000000 мс |
| `--view-min`, `--view-max` | `GALLERY_VIEW_MIN`, `GALLERY_VIEW_MAX` | 10, 30 мс | 1..1000000 мс |
| `--strategy` | `GALLERY_STRATEGY` | `random` | Четыре стратегии из таблицы выше |
| `--seed` | `GALLERY_SEED` | 42 | 0..18446744073709551615 |
| `--delay-ms` | `GALLERY_DELAY_MS` | 0 | 0..60000 мс |
| `--max-active` | `GALLERY_MAX_ACTIVE` | 10000 | 1..10000 |
| `--log` | `GALLERY_LOG` | `gallery.jsonl` | Путь или `-` для отключения |
| `--journal` | `GALLERY_JOURNAL` | `results.csv` | Путь или `-` для отключения |
| `--unlimited` / `--finite` | `GALLERY_UNLIMITED` | 0 | 0 / 1; `--finite` отменяет unlimited |
| `--quiet` | `GALLERY_QUIET` | 0 | 0 / 1 |
| `--json` | `GALLERY_JSON` | 0 | 0 / 1 |

- `--config FILE`: читать файл [KEY=VALUE](configs/demo.env).
- `--interactive`: запросить вместимости, картины, посетителей, интервалы и стратегию.
- Min не должен превышать max.
- В unlimited оба интервала прибытия не могут быть нулевыми.
- Интервалы прибытия и осмотра — время модели.
- `--delay-ms` — реальная пауза после события, включая quiet-режим.
- Подсказки и ошибки идут в stderr.

```sh
./build/gallery --config configs/demo.env --visitors 100 --strategy least-crowded
GALLERY_SEED=91 ./build/gallery --quiet
```

| Файл конфигурации | Правило |
|---|---|
| Разрешено | `KEY=VALUE`, пустые строки, отдельные комментарии `#`, пробелы по краям |
| Булевы значения | Только `0` и `1` |
| Отклоняется | Неизвестный/повторный ключ, неверное число, встроенный NUL, слишком длинная строка |
| Не поддерживается | `export`, кавычки, shell-подстановки и комментарии после значения |

Файл читается как данные. Правила не зависят от интерполяции Docker Compose.
EOF или неверное значение в интерактивном режиме завершает ввод с ошибкой.

## Вывод и статистика

| Канал | Формат | Поведение |
|---|---|---|
| Обычный stdout | Русские события и итог | Время, ID, картина, занятость, действие |
| `--json` | JSONL | Одно событие на строку |
| `--quiet` | JSON | Только итог; имеет приоритет над `--json` |
| `--log FILE` | JSONL | Подробная трасса; файл перезаписывается |
| `--journal FILE` | CSV | Итоговая строка добавляется после запуска |
| stderr | Текст | Подсказки и диагностика |

События: прибытие, ожидание, разрешение на вход, вход, выбор картины,
начало/окончание осмотра, выход, закрытие, отмена и итог.

- JSONL содержит конфигурацию, `seq`, время, ID, занятость, очереди и длительности.
- ID начинаются с 1; 0 обозначает отсутствие участника у служебного события.
- `seq` учитывает конфигурацию, статистику картин и итог.
- Лог и журнал должны быть разными файлами, включая hard-link aliases.
- Запись через файловые дескрипторы обрабатывает короткие записи и EINTR.
- Закрытый pipe даёт ошибку ввода-вывода.
- CSV-блокировка защищает заголовок и строку при независимых параллельных запусках.
- Ожидание блокировки ограничено и прерывается сигналом.
- Для нескольких трасс задавайте разные `--log`.

| Статистика | Что учитывается |
|---|---|
| Посетители | Прибывшие, вошедшие, завершившие, отменённые |
| Просмотры | Начатые и завершённые; также по каждой картине |
| Ожидание | Среднее и максимум у входа и у картины |
| Незавершённое ожидание | Отдельные суммы при прерывании |
| Занятость | Пик галереи и каждой картины |
| Использование мест | Интеграл занятости / вместимость / длительность дня |

## Завершение

- Конечный режим: закрыть вход после последнего прибытия, обслужить очередь, дождаться выхода всех.
- `--visitors 0`: сразу завершить пустой день.
- Unlimited: продолжать прибытия до прерывания.
- Ctrl+C / SIGINT / SIGTERM: отменить незавершённые визиты, освободить места, сохранить частичный итог.
- Прерванный просмотр не засчитывается.
- Исчерпание `--max-active` завершает работу с ошибкой.

| Код выхода | Причина |
|---|---|
| 0 | Нормальное завершение или справка |
| 1 | Ошибка выполнения, ввода-вывода, лимита или инварианта |
| 2 | Неверные входные данные |
| 130 | SIGINT |
| 143 | SIGTERM |

Ошибка сохранения журнала имеет приоритет над кодом сигнала.
При недоступном файле итог в него записать нельзя.

## Сборка и инструменты

| Действие | Команда | Дополнительный инструмент |
|---|---|---|
| Собрать | `cmake --build build --parallel` | C-компилятор |

- Дополнительные инструменты определяются при конфигурации CMake. После установки повторите `cmake -S . -B build`.
- База `build/compile_commands.json` экспортируется для Ninja/Makefile-генераторов.
- clangd и clang-tidy используют семь команд обычной сборки; sanitizer-команды исключены.
- Строгие предупреждения компилятора считаются ошибками.
- clang-tidy: ошибки анализатора/компилятора фатальны; эвристические рекомендации — предупреждения.
- [clang-format](.clang-format): LLVM, 4 пробела, 80 колонок.
- [clang-tidy](.clang-tidy): C analyzer, bugprone, performance, portability.

```sh
clang-format -i src/*.c include/*.h include/internal/*.h
cmake -S . -B build -DCLANG_TIDY_EXECUTABLE=/path/to/clang-tidy
```

## Тесты и эксперименты

- **47 групп**: стратегии, FIFO, пять инвариантов, равные времена событий.
- Крайние случаи: 0/100/300 посетителей, 1000 визитов с одним переиспользуемым слотом.
- Ввод: CLI, среда, файл, приоритеты, переполнение, неверные диапазоны, NUL, EOF.
- Остановка: SIGINT/SIGTERM в конечном и unlimited-режимах.
- Вывод: ошибки файлов/pipe, aliases, занятый и общий CSV.
- Воспроизводимость: одинаковый seed, независимость нагрузки от стратегии, задержка вывода.
- [Независимый валидатор](tests/validate.py) восстанавливает историю и статистику из JSONL.
- Параллелизм разрешён в отдельном тестере: независимые процессы и временные каталоги.

```sh
python3 tests/run.py --binary build/gallery --jobs 8
python3 tests/experiments.py --binary build/gallery --jobs 4 --seeds 24 --output output/experiments
```

| Эксперимент | Значение |
|---|---|
| Объём | 4 стратегии × 24 seed × 2 нагрузки = 192 запуска |
| Один запуск | 200 посетителей, 7 картин |
| Сравнение | Одинаковые прибытия и длительности просмотра при одинаковом seed |
| Низкая нагрузка | Галерея 20, мест у картины 3, прибытия 15..25 мс, осмотр 10..30 мс |
| Плотная нагрузка | Галерея 20, мест у картины 2, прибытия 0..2 мс, осмотр 15..35 мс |
| Агрегаты | [JSON](output/experiments/summary.json), [CSV](output/experiments/summary.csv) |
| Подробности серии | `batch-*/`: все строки журнала, итоги, 8 трасс для seed=0 |

- Старые серии сохраняются локально; сырые `batch-*/` не входят в Git.
- Target `experiments` обновляет агрегаты, используемые отчётом.
- В плотной нагрузке `least-crowded` сократила средний день примерно на 7,64% относительно `ordered`.
- Вывод относится к выбранным условиям. Подробности: [отчёт](output/pdf/report.pdf).

## Docker / Linux

Нужны Docker и работающий daemon.

```sh
docker compose run --build --rm gallery
docker compose run --build --rm gallery --visitors 100 --quiet --strategy ordered
docker compose --profile test run --build --rm tests
docker compose --profile test run --build --rm --entrypoint cmake tests --build build --target sanitize
docker compose --profile experiments run --build --rm experiments
```

| Сервис Compose | Target Dockerfile | Назначение | Файлы на хосте |
|---|---|---|---|
| `gallery` | `runtime` | Один последовательный симулятор | `output/runs/` |
| `tests` | `test` | Независимые тестовые запуски | Временные файлы в контейнере |
| `experiments` | `experiments` | Сравнение стратегий | `output/experiments/` |

- Runtime-образ содержит программу и пример конфигурации.
- Образ инструментов содержит GCC, libc6-dev, CMake, Ninja и Python.
- На Linux/ARM64 проверены все три образа, 47 групп тестов, ASan/UBSan и 192 эксперимента.
- Linux/AMD64 не проверялся.
- Нативные проверки macOS также пройдены.
- Детали: [Dockerfile](Dockerfile), [Compose](compose.yaml), [верификация](docs/verification.md).

## Допущения и ограничения

- Время перемещения между картинами не учитывается.
- Прибытия и длительности осмотра — равномерные целочисленные интервалы.
- События ищутся сканированием; проверки состояния полные.
- RAM ограничена `--max-active`; длительный unlimited-лог может расти.
- Для долгих запусков контролируйте размер лога или используйте `--log -`.
- Общий журнал требует файловую систему с POSIX advisory locks.
