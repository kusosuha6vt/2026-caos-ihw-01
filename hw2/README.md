# Картинная галерея

Консольная модель на C11 для Linux: посетители осматривают все картины, вахтёр допускает их в порядке очереди, вместимость галереи и каждой картины ограничена. `gallery` использует мьютекс и семафоры POSIX, `gallery-cond` — мьютексы и условные переменные.

## Сборка и запуск

Нужны компилятор C11, libc, pthread и Make; для проверок — Python 3. Команды выполняются из `hw2/`. Исходники inih r62 и лицензия включены в `third_party/inih/`, устанавливать библиотеку не нужно.

```sh
make
./build/gallery --config tests/cases/demo.conf --log demo.log
./build/gallery-cond --config tests/cases/contention.conf
./build/gallery --help
```

На macOS доступен `make test-native` для версии с условными переменными. Основную версию проверять в Linux, например через Docker:

```sh
docker build -t ihw-hw2:local .
docker run --rm --mount type=bind,src="$PWD",dst=/work ihw-hw2:local make BUILD=build-linux test
```

Каталоги нативной и Linux-сборки должны различаться. Для 300 посетителей добавить `--visitors 300`, для пустого дня — `--visitors 0`.

## Параметры

Разбор выполняет `getopt_long`: допустимы `--name value`, `--name=value`, однозначные сокращения длинных имён и `-h`. Позиционные аргументы запрещены.

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `--capacity` | 10 | Вместимость галереи с учётом выданных разрешений. |
| `--paintings` | 5 | Число картин. |
| `--painting-capacity` | 3 | Единый предел зрителей у каждой картины. |
| `--visitors` | 100 | Конечное число посетителей. |
| `--arrival-min-ms`, `--arrival-max-ms` | 1, 3 | Интервал перед созданием посетителя, включая первого. |
| `--view-min-ms`, `--view-max-ms` | 1, 5 | Длительность осмотра картины. |
| `--strategy` | `random` | Случайная перестановка картин либо `sequential` по номерам. |
| `--seed` | 42 | Беззнаковое 64-битное начальное значение генераторов. |
| `--display-delay-ms` | 0 | Пауза после осмотра: место картины уже свободно, место галереи ещё занято. |
| `--log` | отсутствует | Перезаписываемый файл трассы и итогов. |
| `--config` | отсутствует | Единственный файл конфигурации. |
| `--help` | — | Справка без запуска потоков. |

Время задаётся в миллисекундах; целые задержки равномерно выбираются из включительного диапазона `[min,max]`, где `min <= max`. Равные границы задают постоянную задержку, нули — отсутствие паузы. Одинаковый `seed` воспроизводит маршруты и назначенные задержки, но не расписание потоков и реальное время.

Технические пределы: 0–4096 посетителей, 1–1024 картины, вместимости 1–2147483647, задержки 0–3600000 мс, `seed` 0–18446744073709551615. Вместимость картины может превышать вместимость галереи. Эти пределы не гарантируют наличия системных ресурсов для всех потоков.

## Конфигурация

Приоритет: **значения по умолчанию → файл → командная строка**, независимо от положения `--config`. Неуказанные настройки сохраняют значения по умолчанию. Например:

```ini
capacity=8
paintings=5
painting-capacity=2
visitors=100
strategy=random
seed=2026
```

Ключи совпадают с полными именами параметров без `--`, кроме `config` и `help`. Файл разбирает inih: разрешены `=` и `:`, пробелы по краям удаляются, последнее значение повторённого ключа побеждает. Строки с `#` или `;` после начальных пробелов — комментарии; внутри строки комментарий `#` должен идти после пробела: `visitors=0 # comment`. Секции, продолжения строк, BOM и NUL запрещены; кавычки и экранирование не обрабатываются. `#` без предшествующего пробела остаётся частью значения; пути также можно задавать через командную строку.

Допускаются только обычные файлы до 65536 байт со строками до 4095 байт. Неизвестные ключи, знаки и посторонние символы в числах, переполнения и неверные диапазоны отклоняются до запуска потоков.

## Вывод и завершение

Формат — JSON Lines с русским пояснением: `config`, события `event`, затем `painting_summary` и общий `summary`. Событие содержит номер `seq`, монотонное время `time_ms`, имя `event`, пояснение `text`, идентификаторы `visitor`/`painting`, счётчики `gallery`/`viewers`/`queue` и назначенную задержку `delay_ms`. Идентификаторы начинаются с 1; 0 означает отсутствие участника/картины.

Основные события: `arrive`, `wait_entrance`, `grant`, `enter`, `choose`, `wait_painting`, `view_begin`, `view_end`, `exit`. Служебные: `queue`, `entrance_closed`, `stop`, `cancel`, `error`, `warden_done`. `gallery` включает зарезервированные места; полученное разрешение картины может ещё не отражаться в `viewers` до регистрации начала осмотра.

При исправном выводе консоль и журнал содержат одинаковую трассу. Итоги показывают созданных, прибывших, допущенных, завершивших и отменённых посетителей, число осмотров, максимумы занятости и причину завершения. При полном штатном запуске число осмотров равно `visitors × paintings`.

После окончания генерации очередь обслуживается полностью. SIGINT/SIGTERM прекращают новые допуски, отменяют ожидающих и прерывают паузу генератора; уже допущенные заканчивают маршрут. Повторный сигнал не сокращает оставшиеся осмотры. SIGUSR1 используется служебным потоком завершения.

| Код | Значение |
| --- | --- |
| 0 | Штатное завершение или справка. |
| 1 | Ошибка ресурсов или вывода; имеет приоритет над кодом сигнала. |
| 2 | Ошибка аргументов или конфигурации. |
| 130 / 143 | Плавное завершение по SIGINT / SIGTERM. |

Журнал открывается до запуска потоков. Запрещены специальные файлы, символьная ссылка в последнем компоненте пути, несколько жёстких ссылок и совпадение с конфигурацией или стандартными потоками вывода. Новый журнал создаётся с правами не шире `0600`; существующий перезаписывается с сохранением прав.

Ошибка записи отключает только неисправное назначение. Ожидание готовности канала ограничено 250 мс на запись; задержки обычной файловой системы этим сроком не ограничены. Поздняя ошибка записи или закрытия может возникнуть после последней строки статистики: окончательный статус задаёт код процесса. На время записи меняется O_NONBLOCK; параллельно менять флаги того же открытого файла извне нельзя.

## Структура и проверки

| Файлы | Назначение |
| --- | --- |
| `src/simulation.c` | Ресурсы, создание/присоединение потоков, сигналы. |
| `src/gallery.c` | Очередь, допуск и поведение посетителей. |
| `src/events.c` | Вывод конфигурации, событий и итогов. |
| `src/config.c`, `io.c`, `random.c`, `permit.c` | Параметры, ввод-вывод, случайность и разрешения. |
| `include/`, `src/simulation_internal.h` | Открытые интерфейсы и закрытое состояние модели. |

В Linux доступны `make test`, `make analyze`, `make sanitize`, `make tsan`; проверка готовой трассы — `python3 tests/check_trace.py demo.log`. `make test` также проверяет самостоятельное включение заголовков. Тестовые сборки имитируют отказы создания посетителей и подготовки разрешений. Результаты и исключения диагностики приведены в отчёте. Для TSan в Docker нужен отдельный запуск:

```sh
docker run --rm --security-opt seccomp=unconfined --mount type=bind,src="$PWD",dst=/work ihw-hw2:local make tsan
```

`make docs` создаёт обе редакции Doxygen в `docs/generated/html/index.html` и `docs/generated/condition/html/index.html`; предупреждения считаются ошибками. `make format` и `make format-check` используют clang-format 14 и `.clang-format` только для собственных исходников. На macOS эти три цели автоматически используют Docker; контейнер содержит Doxygen 1.9.4.

Обоснование модели, результаты проверок, ограничения и описание использования ИИ — в [REPORT.md](REPORT.md).
